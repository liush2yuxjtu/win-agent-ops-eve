# 运维工作台已批准设计

状态：**已采用**（2026-09-11）

## 目的

让非技术人员不用从长日志里找答案。Agent 负责把原始监控变成可分诊的问题、复现探针和可比较路线；人保留批准、反馈和最终执行权。

参考 Mock：`product-demo-v9/`。真实实现：`web/`，入口 `http://127.0.0.1:8766/`。

## 三步交互契约

### 1. TRIAGE

- 读取保存的监控证据。
- 原始长日志默认收起，仍可按需查看。
- Agent 为全部现有问题生成标题、描述和 `P0/P1/P2/P3` 优先级。
- 人只选择一个问题继续，不要求一次解决全部问题。

### 2. PROBE · ONE APPROVAL GATE

- Agent 先写清探针目的、采集字段和范围。
- 点击“添加探针”只打开一次 `AskUserQuestion`。
- 只有“批准并开始”继续；取消不添加。
- 批准后 Agent 展示四步：读取问题、添加探针、寻找复现、等待人工反馈。
- 人反馈三种结果：问题已复现、问题已解决、输入文字反馈。
- 探针流程不直接修复业务；真实生产探针仍由人按批准范围手工添加。

### 3. ROUTE & APPLY FIX

- Probe 完成并收到人工反馈后，Agent 给出 5 条独立处理路线。
- 每条路线显示：复现探针、解决动作、Blast Radius、适用条件、风险、验收和回退。
- 人选择路线并点击应用；真实工作台只记录人工采纳/暂缓，不自动执行生产修复。
- 不再打开第二个审批弹窗。

## 视觉规则

- 单条垂直信息流，不使用占据首屏的大型 Tab 或多窗口舞台。
- 长文本收起，标题、状态、优先级和下一动作先显示。
- Agent 过程必须可见，避免只有无意义的 loading。
- 每个主要动作必须产生可观察状态变化，并用 `aria-live` 告知。
- 真实页面可使用终端语言和暗色面板，但必须保持普通浏览器文字可读、键盘可操作、移动端无横向溢出。
- Mock 与真实页面共享术语和顺序；Mock 不冒充真实探针或生产修复。

## 证据与边界

- 真实诊断仍走现有 Mac mini Eve/CPA 路由和 SQLite 版本记录。
- 设计录制必须访问真实工作台，不录制 `product-demo-v9` 代替。
- 录制可使用隔离数据库验证交互，但不能使用 fixture 服务、模型替换或 localStorage 冒充业务结果。
- “应用路线”在当前工作台语义中是人工记录，不等于业务系统已修复；真实执行与反馈由团队完成。
- 凭据、Cookie、私有运行态和生产写工具不进入页面、录制目录或 Git。

## 维护

修改流程、术语或视觉层级时，先更新本文件和 `docs/REAL-APP-RECORDING.md`，再同步 `web/` 与 `product-demo-v9/`。`web/` 是真实工作台真源，`product-demo-v9/` 是本地 Mock 参考，不反向覆盖真实数据和后端边界。
