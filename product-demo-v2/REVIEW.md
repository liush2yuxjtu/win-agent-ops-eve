# 领导版产品演示 V2

状态为等待设计批准。入口为 `index.html`。这是一份独立、无构建、无外链的可交互原型，不修改正式工作台、不调用模型、不录制视频。

已按最新反馈移除顶部五个功能菜单。页面内改为带原创静态背景的 HTML 产品窗口：左侧问题队列、中间业务分诊与方案、右侧证据和决策摘要。点击“体验异常处理”可以联动归并、问题选择与分诊；点击问题直接进入业务分诊。原始信号、决策历史、复核与潜在风险从相关窗口中的上下文按钮进入，不另做五项功能导航。画面是实际可操作 DOM，不是截图或视频；仍明确标记为本地模拟。

## 五项能力与体验

1. 红灯发现。点击合并按钮，三条样例信号归为一个问题；队列和证据说明联动，保留来源与时间，禁止重复计入。
2. 领导版分诊。选择不同问题，同时更新业务影响、紧急程度、事实、推测、待核实信息和责任范围。没有代码、命令或无依据的个人追责。
3. 独立方案。登录问题五条，订单问题四条。每条可单独选择，主面板和右侧摘要联动。展示收益、条件、时间与资源、风险、验收、退出和回退。第一建议有理由，不强制采纳。人工受理和限制新增受理注明只保障业务或止损，不冒充系统修复。
4. 长期历史。选择理由必填；保存原始证据、当时的判断、全部备选方案、推荐方案 ID 和所选方案快照。结果绑定具体选择，支持有效、无效、复发、疑似误报和未验证。刷新可保留，导出包含完整关联。原型仅使用浏览器 localStorage；正式系统目标为 SQLite，尚未在原型中接入。
5. 质量改进。模拟扫描增加一个表面正常但业务可能停滞的候选，更新队列；处理反馈形成复核关注点。明确区分潜在问题、已核实故障和疑似误报。首选命中、前五覆盖、误报和漏报均显示待真实验证，不预填准确率，不伪装模型评测已经运行。

## 决策依据

按领域建模原则，信号、问题、判断、方案、选择和处理结果分开，避免“选择了”变成“执行了”或“修好了”。按真实验证原则，浏览器实际走完归并、切换方案、保存与刷新、结果反馈、潜在风险、复核和导出。

保留现有暖白和绿色视觉；主窗呈现当前能力，左右窗口分别是问题队列与决策摘要。不加入开发者终端或拖窗负担。采用原生单文件，是为了本轮离线评审，不引入新的前端项目或设计系统。

## 验证

`python3 verify.py` 的结果见 `verification.json`。覆盖五项能力的状态联动、无效输入、文本安全、三种宽度的页面溢出、键盘操作和无外部请求。没有截屏或录制。

另用命名 agent-browser 会话验证了归并、方案选择与摘要联动。已安装 CLI 不支持 `a11y` 子命令，`a11y.json` 保存实际错误。因此不宣称通过完整自动化无障碍审计；本轮只完成语义控件、标签、键盘和布局检查。浏览器会话均已关闭。

设计批准后，再把已认可交互接入正式数据、SQLite 与 Eve/CPA，并按批准版本录制。当前导出的是演示记录，不是实际运维决定或执行授权。
